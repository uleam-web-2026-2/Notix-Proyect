API Notix

Referencia de la API implementada en el backend de Notix. La entidad central es Tarea, organizada en columnas y tableros.

Base local indicada por la configuración del proyecto: http://localhost:8080.

Tecnologías y alcance

  • Go 1.23+, net/http con ServeMux, GORM y PostgreSQL.
  • Autenticación JWT (firma HS256) y contraseñas almacenadas con bcrypt.
  • La API publica las rutas enumeradas en esta página. Otras operaciones descritas como planificadas en docs/openapi.yaml no están registradas en el router.

Las rutas se verificaron en internal/httpapi/router.go. No se documentan como disponibles las operaciones planificadas de tableros, columnas, compartir, comentarios o CRUD adicional.

Autenticación y permisos

POST /login recibe correo y clave. Si son válidos, responde con un JWT Bearer, su expiración y el usuario con su rol. El token incluye el identificador y rol; la duración se configura mediante TOKEN_TTL (por defecto, 8 horas).

Para rutas protegidas envía Authorization: Bearer <token>. El propietario y el colaborador con invitación activa pueden consultar tareas del tablero. Ambos pueden crear tareas en un tablero al que tienen acceso; solo el propietario puede cambiar estados.

Iniciar sesión

curl -i -X POST http://localhost:8080/login \
  -H 'Content-Type: application/json' \
  -d '{"correo":"propietaria@notix.test","clave":"Prop-demo-2026"}'

La inicialización de demostración siembra las cuentas anteriores y colaborador@notix.test / Colab-demo-2026. Son credenciales de demostración definidas en database/database.go; no son credenciales personales.

Usar el token

curl -i http://localhost:8080/tableros/1/tareas \
  -H 'Authorization: Bearer <token>'

El ID de tablero del ejemplo es ilustrativo: el servidor imprime los IDs sembrados al iniciar; con un volumen existente pueden variar.

Rutas implementadas

Método y rutaSesiónUso y parámetrosRespuesta normal
GET /healthNoComprobación de disponibilidad; no recibe parámetros.200 {"status":"ok"}
POST /loginNoJSON requerido: correo y clave.200 con token, token_type, expires_at y usuario.
GET /tableros/{tableroID}/tareasBearertableroID: entero positivo; usuario debe tener acceso al tablero.200 con arreglo de tareas.
GET /tareas/{id}Bearerid: entero positivo; usuario debe tener acceso al tablero de la tarea.200 con la tarea.
POST /tareasBearerJSON: titulo requerido (1–150 caracteres tras recortar espacios), contenido opcional (máximo 5000 caracteres), columna_id entero positivo. La columna debe pertenecer a un tablero accesible.201 con tarea creada, inicialmente pendiente.
PATCH /tareas/{id}/estadoBearerid: entero positivo. JSON: estado. Solo el propietario puede cambiarlo.200 con tarea actualizada.

Estados permitidos: pendiente, en_proceso y completado. Transiciones aceptadas: pendiente → en_proceso; en_proceso → pendiente o completado; completado → en_proceso.

Cuerpos y respuestas de ejemplo

Crear tarea

POST /tareas
Authorization: Bearer <token>
Content-Type: application/json

{
  "titulo": "Preparar entrega",
  "contenido": "Revisar los requisitos",
  "columna_id": 1
}

Cambiar estado

PATCH /tareas/1/estado
Authorization: Bearer <token>
Content-Type: application/json

{"estado":"en_proceso"}

Forma de error

{
  "error": {
    "code": "forbidden",
    "message": "No tienes permiso para realizar esta acción."
  }
}

Errores y códigos HTTP

CódigoCuándo lo devuelve la implementación
400JSON inválido, campos JSON desconocidos, más de un objeto JSON o ID que no es entero positivo.
401Falta un Bearer válido en rutas protegidas o las credenciales de inicio de sesión no coinciden.
403El usuario no tiene acceso al tablero o un colaborador intenta cambiar el estado.
404No se encontró el recurso solicitado.
409La tarea cambió concurrentemente y no se pudo aplicar la actualización condicional.
422Validación de datos de tarea o transición de estado no permitida.
500Error interno no clasificado; se registra en el servidor y se devuelve un mensaje genérico.

La ruta inexistente o el método no registrado se resuelve por el ServeMux estándar de Go; no hay un formato JSON de error propio para esos casos.
